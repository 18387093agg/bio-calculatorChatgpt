# Known limitations
This is an estimation framework, not a metabolic simulation, laboratory measurement, or diagnostic tool. Quantitative absorption is intentionally limited to source-aware iron and B12 ranges. Systemic-pool, intracellular, active-form, generic pathology, and unsupported interaction stages remain unavailable rather than zero.

The local browser bundle contains ten explicitly labeled demonstration foods. The 87-food manifest and validated FDC import boundary are complete, but the repository does not embed 87 nutrient profiles because this audit environment has no authorized FoodData Central data/API response and values must not be invented. A production operator must resolve and review the manifest against current Foundation/SR records and load the canonical SQL database with value-level provenance.

Browser persistence is local storage only. The Supabase schema and RLS are ready for an authenticated adapter, but no cross-device/authenticated client is claimed and no service-role credential is shipped. Preparation-specific retention/yield is calculated only when an evidence-linked record exists; selecting a preparation label in the demo does not invent a universal cooking factor.
